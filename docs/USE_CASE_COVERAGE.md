## Existing code-level constraints recorded in the previous coverage draft

These are implementation observations from the pre-existing coverage document, not verified SRS requirements:

- One table can have at most one `ACTIVE` or `PAUSED` play session.
- Active reservations for the same table cannot overlap.
- A table transfer closes the old rate segment and opens a new segment using the destination table's rate.
- Paused time is excluded from table charges.
- Inventory is deducted when an order item is served; the handler checks stock before deduction.
- Paid invoices cannot be adjusted or cancelled through the documented handler paths.
- Membership benefits are recorded as invoice adjustments.
- Cash payment requires the cashier to have an open shift.
- The app exposes audit log retrieval; no audit edit/delete action was found in the action dispatcher.
